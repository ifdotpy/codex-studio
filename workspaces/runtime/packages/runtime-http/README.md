# `studio-runtime-http`

## Change Contract

- **Responsibility:** own the committed OpenAPI authority, generated Rust DTOs,
  schema identity, Axum router and HTTP boundary compatibility rules.
- **Public interface:** `router`, `HttpState`, `api_schema_hash`, and
  `operations`.
- **Forbidden dependencies:** Python runtime modules, SQLite, provider SDKs,
  and the runtime-server application.
- **Invariants:** schema bytes stay canonicalizer-v3 stable; documented but
  unimplemented operations return the common 501 error; synchronous domain
  interfaces remain outside the async edge.
- **Configuration owner:** `studio-runtime-server` supplies listener identity,
  process token, workspace identity, and local diagnostics to `HttpState`.
- **Focused check:** `cargo nextest run -p studio-runtime-http`.

`openapi.json` is the full, human-readable API authority and outlives the Python
application. It is emitted with sorted keys and two-space indentation by the
Python exporter's deterministic JSON writer; Oxfmt intentionally does not own
this file. Run `pnpm run api:generate` to refresh this document, TypeScript
types/hash, and compile the build-generated Rust DTOs. `pnpm run api:check`
checks model/document drift, byte-for-byte TypeScript output drift, and Rust
DTO generation. TypeScript types are rendered from the full document so the
generated client retains its titles and descriptions.

The server removes only OpenAPI documentation metadata, sorts the documented
schema unions and map keys, then hashes compact JSON with SHA-256. This is the
Rust implementation of Python's canonicalizer-v3 rules, so editing prose does
not change the API hash.

Rust DTOs are generated by `openapi-to-rust` 0.22.0 in `build.rs`, into Cargo's
`OUT_DIR`, and included from there. The generated files and an extra generator
binary are not checked in. The exact generator version is a build dependency
and is pinned by `Cargo.lock`. On the measurement host, a clean package build
took 28.2 seconds and an incremental build took 0.05 seconds. `cargo tree`
reported 197 packages with normal and build dependencies combined, 74 in the
normal runtime graph.

## Route-group pattern

Each route group lives in its own `src/routes/<group>.rs` module. A handler
accepts Axum extractors such as `State<HttpState>`, `Path`, `Query` and `Json`
and returns `Json<T>` or `Result<Json<T>, ApiError>`. `ApiError` serializes
through the shared `{ "error": "..." }` envelope. Put only the small,
route-specific port needed by that group in state. For synchronous store work,
clone the port and inputs, call it inside `tokio::task::spawn_blocking`, and
map join/domain failures to `ApiError`; never retain a store transaction across
an await. Register the route in the router and add its `(method, path)` to the
ledger's `IMPLEMENTED` set only after it returns the implemented contract and
shared schema header. The conformance command discovers consumer suites and
writes its detailed ledger beneath `XDG_CACHE_HOME`, outside the checkout.

Direct dependencies introduced by this package: Axum 0.8.9 (MIT), Tokio
1.53.2 (MIT), SHA-2 0.10.9 (MIT OR Apache-2.0; schema hash), subtle 2.6.1
(MIT OR Apache-2.0; constant-time token comparison), and openapi-to-rust
0.22.0 (MIT; build-time DTO generation). Serde and serde_json are existing
workspace dependencies. The build-only generator pulls its transitive parsing,
schema-validation and code-formatting dependencies into the build graph, not
the runtime dependency graph.

Generated files should be refreshed through `pnpm run api:generate`; do not edit
them by hand.
