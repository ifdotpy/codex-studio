# `studio-runtime-http`

## Change Contract

- **Responsibility:** own the committed OpenAPI authority, generated Rust DTOs,
  schema identity, Axum router and HTTP boundary compatibility rules.
- **Public interface:** `router`, `HttpState`, `api_schema_hash`, and
  `operations`.
- **Forbidden dependencies:** Python runtime modules, SQLite, provider SDKs,
  and the runtime-server application.
- **Invariants:** schema bytes stay canonicalizer-v3 stable; documented but
  unimplemented operations return the common 501 error; synchronous domain
  interfaces remain outside the async edge.
- **Configuration owner:** `studio-runtime-server` supplies listener identity,
  process token, workspace identity, and local diagnostics to `HttpState`.
- **Focused check:** `cargo nextest run -p studio-runtime-http`.

`openapi.json` is the full, human-readable API authority and outlives the Python
application. It is emitted with sorted keys and two-space indentation by the
Python exporter's deterministic JSON writer; Oxfmt intentionally does not own
this file. Run `pnpm run api:generate` to refresh this document, TypeScript
types/hash, and compile the build-generated Rust DTOs. `pnpm run api:check`
checks model/document drift, byte-for-byte TypeScript output drift, and Rust
DTO generation. TypeScript types are rendered from the full document so the
generated client retains its titles and descriptions.

The server removes only OpenAPI documentation metadata, sorts the documented
schema unions and map keys explicitly, then hashes compact JSON with SHA-256.
This is the Rust implementation of Python's canonicalizer-v3 rules, so editing
prose does not change the API hash.

The `workspace_keeps_serde_json_maps_sorted` test in `studio-runtime-http`
checks the normal workspace feature graph and rejects
`serde_json/arbitrary_precision` and `serde_json/preserve_order`.
`arbitrary_precision` changes number values into serde_json's private wrapper
object; `preserve_order` changes `serde_json::Map` from sorted to insertion
order. Canonical output in several crates relies on sorted keys; code that
needs insertion order must parse ordered pairs locally.

Rust DTOs are generated by `openapi-to-rust` 0.22.0 in `build.rs`, into Cargo's
`OUT_DIR`, and included from there. The generated files and an extra generator
binary are not checked in. The exact generator version is a build dependency
and is pinned by `Cargo.lock`. `jsonschema` is a runtime dependency for
validating requests against the committed OpenAPI schemas. The build-only
generator is a separate dependency graph.

## Route-group pattern

Each route group lives in its own `src/routes/<group>.rs` module. A handler
accepts `State<HttpState>`, `ApiJson<T>`, `ApiJsonOptional<T>`, `ApiHeaders`, or
`QueryParams` and returns `Json<T>` or `Result<Json<T>, ApiError>`. The boundary
validates each registered request before invoking a handler, and the extractors
read the resulting `ValidatedRequest`; a raw body handler therefore runs only
after shared validation. `ApiError` serializes through the shared
`{ "error": "..." }` envelope. Put only the small, route-specific port needed
by that group in state. For synchronous store work,
clone the port and inputs, call it inside `tokio::task::spawn_blocking`, and
map join/domain failures to `ApiError`; never retain a store transaction across
an await.

Export a `routes() -> RouteGroup` from the group module. Register each route
with one method-specific constructor such as `get(path, status, handler)` or
`post(path, status, handler)`. That call creates the Axum method route and its
manifest descriptor together. Add the module's `routes()` call once in
`routes::groups()`; the composer validates every registration against the
committed OpenAPI authority and rejects undocumented or repeated operations.
Adding a route inside a group needs no shared registration edit; adding a group
needs one line in the module list. The ledger reads operation status from these
registrations, so route authors do not maintain a second allowlist. Use
`OperationStatus::Partial` with named `Dependency` values when a handler can
serve only some cases, and use `dependency_unavailable` for its declared 501
response. Documented operations without a handler return the shared 501
envelope. The conformance command discovers consumer suites, records matching
HTTP assertions per operation, and writes its detailed ledger beneath
`XDG_CACHE_HOME`, outside the checkout.

To migrate a route module written against the previous pattern, replace each
`Router::route(...)` plus its separate `Operation::new(method, path)` descriptor
with one `get(path, status, handler)`, `post(path, status, handler)`, or other
method-specific registration in the module's `RouteGroup`. Remove the separate
descriptor list. Keep the existing handler and body unchanged.

Use `ApiJson<T>` for JSON bodies and `QueryParams` as the only query-string
reader. `QueryParams` exposes only schema-validated typed values. Repeated values for a declared scalar query parameter are
rejected with a located 400, including percent-encoded names and repetitions
whose values are all empty; declared array parameters retain all occurrences.
Convert values through the operation's
OpenAPI schema and reject undeclared names. Do not use Axum's `Path`, `Query`,
or `Json` input extractors. The router compiles validators for documented operations from
`openapi.json` at startup, validates before handlers run, and stores the typed
values in request extensions. Scalar header parameters are converted by their
declared schema, matched case-insensitively, and available in
`ValidatedRequest.headers`; repeated values and non-scalar header schemas fail
validation or startup as appropriate. Validation errors use one envelope with a short
message and the first problem's location. Request schema constraints come only
from OpenAPI; JSON bodies are validated strictly, and parameter strings are
converted generically according to their declared schema type. Integer
parameter text accepts ASCII decimal digits (and a leading minus where the
schema permits negative values); leading zeroes are accepted, while plus signs,
whitespace, underscores, and decimal points are rejected.

The shared middleware checks byte limits before parsing, including on
federation paths that bypass the general JSON prebuffer. Missing optional bodies
remain absent, required bodies are refused, and an empty optional chunked body
is treated as absent after reading its bounded bytes. Non-empty bodies require
the documented JSON media type. Duplicate JSON object keys use the last value,
matching Python's `json` parser. It performs an iterative depth scan before
parsing and accepts up to 127 nested arrays or
objects, matching serde_json's parser limit. The byte limits come from
`studio_api/middleware.py::_request_limit`: 256 KiB by default and for
federation, 28 MiB for assets, and 6 MiB for projects and voice audio. The
127-level nesting cap is a deliberate safety limit; deeper JSON receives a 400
validation response before serde_json parses it. The scanner and body reader are
linear in the bounded request size. Schema
regex patterns are fixed in the committed document and are compiled once with
`jsonschema::PatternOptions::regex`, which guarantees linear-time matching.
The document's patterns use the supported regex subset; unsupported patterns
fail validator compilation at startup. The body read has a 10-second timeout from
`studio_api/middleware.py`. Remote references are rejected and local component
references are resolved from the embedded document only. `jsonschema` has
default features disabled, so its HTTP and file retrieval features are not
compiled; this crate also rejects every non-local `$ref` before validator
construction.

Query names are checked against the operation's declared OpenAPI parameter
names before schema validation. OpenAPI does not express rejection of an
undeclared query name as a request-level rule, so the shared validator applies
this one global rule and reports the first unknown name at `query/<name>`.
The optional safe-integer audit switch in the validator checks request schemas
when each operation is compiled. Production startup compiles registered route
operations only; the fast-tier all-authority compile test is what checks every
operation in the document when this switch is enabled.

Run the shared corpus differential with the prepared Python interpreter using
`python3 workspaces/runtime/apps/server/src/codex_python.py --exec workspaces/runtime/apps/server/tests/http_runtime_extractor_differential.py`.

### Known differences from the Python server

- Validation errors use a short `error` and one `location`; the Python boundary
  is being aligned to that envelope. The differential compares validation
  acceptance and status, and checks the envelope shape on refusals.
- Rust rejects JSON nested beyond 127 containers to bound parser stack use.
  The real Python boundary uses `json.loads` and its runtime recursion guard.
- JSON Schema considers an integral JSON decimal such as `1.0` an integer,
  while the current Python `StrictInt` models reject it. This standard
  validator behavior is intentional; typed route DTOs will still reject a
  value they cannot deserialize. The corpus does not generate integral
  decimal JSON bodies as rejection cases.
- Free-form `JsonValue` is opaque. `serde_json` preserves integers through
  `u64::MAX`; larger integer tokens are carried as `f64`, so precision can be
  lost above `2^64`. This is accepted for opaque payloads because no client
  produces such integers. Typed integer fields are being bounded by the
  schema-tightening change; until it lands, the differential allows only the
  exact observed out-of-range integer cases whose Rust value is an `f64` while
  Python retains an integer.
- Parameter strings are converted by their declared schema. Integer parameter
  text accepts ASCII decimal digits, leading zeroes, and a leading minus only
  where negative values are allowed; plus signs, spaces, underscores,
  decimals, and empty values are rejected. Repeated scalar query parameters
  are rejected even when names are percent-encoded or all values are empty;
  arrays retain repeated occurrences.
- The finite expected-difference table has temporary entries for known
  pre-tightening Python/OpenAPI differences and permanent entries for the
  rename, draft identity, and preference key/scope rules. Each entry names an
  operation and generated case, the status from both sides, and its cause. Any
  unlisted mismatch, exception, 5xx, or accepted-value difference fails the
  differential. For generated predicate classes, a 400 refusal from both sides
  is recorded as agreement when Rust includes its located error envelope; each
  class must still contain at least one case with its exact expected difference.
  Agreement counts are reported per cause. The differential stubs route
  handlers, so handler-level rules are exercised separately: rename identity by
  `studio_api.tests.test_main_integration.MainIntegrationTests.test_delivery_and_smart_rename_require_identity_before_dispatch`,
  draft application by `sync-first-draft-http-contract.py`, and preference
  key/scope validation by `studio_api.sync.test_preferences.PreferenceTests.test_validation`. Protocol version
  negotiation (HTTP 426) is covered on Python by
  `sync-protocol-http-contract.py`; the Rust sync stream slice must add its own
  handler-level negotiation test.

The undocumented `POST /api/voice/{action}` catch-all remains registered as in
the Python server; its action is not part of the OpenAPI operation inventory.

The conformance ledger generates the OpenAPI request corpus from
`openapi.json` into a temporary directory and passes its path to both probes.
The Rust corpus test is ignored during ordinary test runs and is invoked by the
ledger with that generated file. The corpus and its summary are derived output,
so neither is committed; the summary duplicates counts from the corpus and has
no hand-maintained meaning.
The Rust corpus observation goes through echo handlers registered through the
normal composer, plus the real router, middleware, validation, and extractors
in-process; domain services remain stubbed. The Python differential runs through FastAPI
route signatures, app-wide dependencies, boundary, and exception handlers
in-process. Every generated request is compared for acceptance and status;
accepted body and parameter values are compared after typing, and rejected
responses are checked for the standard error-envelope shape. Signed federation
operations are included; the Python probe's stub handlers replace signature
verification while the request models and boundary still run.

Direct dependencies include Axum 0.8.9 (MIT), jsonschema 0.49.9 (MIT; runtime
validation against the committed OpenAPI schemas, declared with
`default-features = false` and no optional formats or retrieval features),
form_urlencoded 1.2.2,
serde_path_to_error 0.1.20, Tokio 1.53.2 (MIT), futures-util 0.3.34 (MIT OR
Apache-2.0; panic-safe response middleware), SHA-2 0.11.0 (MIT OR Apache-2.0;
schema hash), subtle 2.6.1 (MIT OR Apache-2.0; constant-time token comparison),
and openapi-to-rust 0.22.0 (MIT; build-time DTO generation).
Tower 0.5.3 is a test-only dependency. Serde and serde_json are existing
workspace dependencies. The build-only generator pulls its transitive parsing,
schema-validation and code-formatting dependencies into the build graph, not
the runtime dependency graph.

Generated files should be refreshed through `pnpm run api:generate`; do not edit
them by hand.
