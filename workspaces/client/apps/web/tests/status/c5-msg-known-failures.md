# Checkpoint 5 message browser known failures

No product failure was confirmed for `tool-limit-history-ui`. The original second request followed a fixture transition that changed thread identity and terminal/latest-error fields. A thread-only adjustment exposed another valid partial batch when the transcript's latest error arrived after the entity seed. The final fixture creates one terminal `fixtureAgent` and shares it between the entity snapshot and transcript, leaving the one-read assertion enabled; its loaded run passed 20/20. In production, agent entity and transcript are separate sync resources, so a just-failed agent can be observed before its terminal transcript update arrives; a read for the entity's new state can be legitimate in that transient. This test measures batching from a consistent starting record and does not assert behavior across that transition.
