# Load-sensitive browser spec fixes: group A

| Spec                                    | Cause and fix                                                                                                                                                                                                                                                                                                        | Class | Solo evidence                                                                             |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- | ----------------------------------------------------------------------------------------- |
| `messages/selection-quote-ui.spec.mjs`  | The spec clicked the quote toolbar immediately after setting a browser selection, before the asynchronous `selectionchange` handler made the toolbar visible. The selection helper now waits for that visible state; fixture startup also honors `PYTHON` so it uses the configured dependency-equipped interpreter. | 1     | `--repeat-each=3 --workers=1`: 3/3 passed, 20.9 s.                                        |
| `models/worker-model-ui.spec.mjs`       | The mock failed only the first catalog request, so an automatic resource refresh could consume the 503 before the explicit retry UI was reached. Keep reads unavailable until the request includes `retry=1`, then serve the catalog; this makes the retry path independent of concurrent request order.             | 1     | `--repeat-each=3 --workers=1`: 3/3 passed, 33.3 s.                                        |
| `sidebar/sidebar-drag-browser.spec.mjs` | The held-save setup waited for a separate page response event after releasing the intercepted request. It now awaits a promise resolved by the route after that exact response is fulfilled, so setup synchronization follows the gate it controls.                                                                  | 1     | `--repeat-each=3 --workers=1`: 9/9 passed, including 3 expected overlap failures; 57.0 s. |

Combined stress check: all three specs passed 15/15 in 51.4 s with `--workers=4 --repeat-each=3` while eight CPU busy loops ran: `for _ in 1 2 3 4 5 6 7 8; do yes >/dev/null & busy_pids+=("$!"); done`. The command installed an exit trap to kill and wait for each loop; `pgrep -xc yes` returned 0 afterward.
