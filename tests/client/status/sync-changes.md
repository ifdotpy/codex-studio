# Sync browser spec changes

- `errors/native-error-ui.spec.mjs`: expand the account and feature warning Details disclosures before checking their JSON payloads. Class 2, stale expectation after `b3e73f2e` wrapped warning details in `<details>`.
- `errors/native-error-ui.spec.mjs`: expand the retrying phase's Details disclosure before checking its diagnostic text and JSON. Class 2, `AgentPhase.tsx` renders reconnect details inside a collapsed `<details>` disclosure.
- `errors/native-error-ui.spec.mjs`: restore the provider's structured object `message` and `additionalDetails` case, including code and attempt assertions. Class 3, fixed by PR #25 (`8afd4232`) widening the sync DTO fields; `dabd21c8` added the structured-details rendering contract.
- `errors/native-error-ui.spec.mjs`: assert the retry Details disclosure remains open after the in-place status update. Class 2, this behavior was previously hidden by conditionally clicking only when closed.
- `errors/native-error-ui.spec.mjs`: configure the fixture's capacity retry deadlines to 60 seconds so the scheduled retry remains visible through the UI assertions and cancellation. Class 1, the production default 10-second timer advanced to `starting` before the test could inspect it.
- `errors/native-error-ui.spec.mjs`: assert the account sign-in recovery title replacing the former capacity title in the native error banner; retain the separate exact capacity warning assertion. Class 2, `c461c430` added auth recovery UI that intentionally takes precedence while capacity retry remains visible in its notice.
- `errors/structured-operational-errors-ui.spec.mjs`: pass the request reason as a string and assert its visible summary. Class 1, the app-server protocol declares `CommandExecutionRequestApprovalParams.reason` as `Option<String>`; the prior object fixture violated that contract. `RequestParamsDto.reason` and the renderer's string-only reader match the actual request producer.
- `errors/structured-operational-errors-ui.spec.mjs`: scope the post-retry diagnostic locator to `.dictation-item .dictation-error`. Class 2, the row-scoped exact-text query targets the diagnostic owner and preserves the assertion after the page-wide exact-text locator timed out despite the text in the row.
- `errors/structured-operational-errors-ui.spec.mjs`: serve the local harness's sync endpoints through `handleEntitySyncFixtureRequest` and pass sync requests through to it. Class 1, the catch-all API stub supplied no valid sync identity, baseline, or requested panel resource, so `AgentPanel` never started its read; `e3ae54c6` adds requested resources to the initial fixture stream frame.
- `errors/tool-limit-history-ui.spec.mjs`: use the current entity sync contract and stream handshake, and provide the transcript through the scoped entity pull with an advancing sequence on reload. Class 1, the old fixture rejected identity as unsupported and served transcript only through the legacy endpoint; persisted sync cursors then correctly ignored a changed transcript whose fixture sequence stayed at 1.
- `errors/tool-limit-history-ui.spec.mjs`: keep the injected analytics failure active until the explicit Retry click, and wait for the initial entity pull before changing the transcript sequence. Class 2, a second read could finish before the UI exposed the failed state, and repeat runs could reload before the fixture established its initial sync checkpoint.
- `errors/ux-request-recovery-browser.spec.mjs`: update the directory picker locators to “Open path” and “Add project”. Class 2, `81bc27a5` changed the picker labels.
- `errors/ux-request-recovery-browser.spec.mjs`: explicitly start the isolated accounts fixture's initial read and only count POSTs as writes. Class 1, the hook refresh is resource-driven and incidental account tile GETs previously shifted the simulated mutation response.
- `errors/ux-request-recovery-browser.spec.mjs`: add current API schema headers to intercepted API replies. Class 1, fixture API responses must identify the current schema.
- `errors/ux-request-recovery-browser.spec.mjs`: select and inspect project defaults through the AccountTiles group and its account button, including disabled and selected values while a request is unresolved. Class 2, `f4f176f1` replaced the old account select with account tiles.
- `sync/disconnect-recovery-ui.spec.mjs`: assert the unconfirmed recovery summary in the status region and inspect the returned diagnostic in the recovery banner's own Details disclosure. Class 2, `660c67bd` separates the user-facing summary from raw diagnostic details; the test still verifies both.
- `sync/draft-sync-ui.spec.mjs`: primary case kept on real time as a stopgap pending owner approval (class 4 exception): `test.setTimeout(180_000)` and at least 55 seconds of fixed real sleeps remain. Virtual-clock conversion failed the draft convergence and A→B restart bound (observed 8.15s against 3.9s); a mixed-clock `pauseAt(browserNow)` attempt failed because Playwright considered the target in the past. One `fastForward(0)` run passed in 48s, but it did not reach the required 3/3; the restored origin/main spec passed 3/3 at about 1.8 minutes each. The attempted branch naming/comment improvements for the restart-storm winner were not retained because the required outcome was the origin/main spec without code edits.
- `sync/sync-read-retry-browser.spec.mjs`: add the generated API schema hash to JSON responses from the local sync fixture. Class 1, `/api/sync/identity` rejects a successful response without the schema hash, so the stream closes before retry behavior can run.
- `sync/sync-required-browser.spec.mjs`: add API schema headers to fixture identity responses and verify automatic recovery through the product's 1s retry after the identity endpoint recovers; the separate explicit-activity case still covers retry-budget recovery. Class 1, successful identity responses require the schema hash.
- `sync/transcript-cache-refetch-browser.spec.mjs`: return an empty baseline for the initial `state:entities:v1` pull before the transcript-specific reads, and include generation/maxSeq plus `_deleted: false` in pull envelopes. Class 1 for the initial entity-scope pull (`syncDatabase()` always starts there); class 2 for matching the current entity response contract.
- `errors/tool-limit-history-ui.spec.mjs`: preserve the fixture helper's generation and maxSeq envelope, use distinct increasing document sequences and matching checkpoints, respect the requested after cursor, and publish resourceVersions for subscribed resources. Class 2, the old fixture assigned the same sequence to each returned document and omitted envelope fields supplied by `entityPullFixture`.
- `errors/ux-request-recovery-browser.spec.mjs`: serve the expected limits response and sync identity, stream handshake, and empty pull explicitly; fail other unknown GET requests instead of returning an empty success body. Class 2, a catch-all response masked unhandled fixture reads.
- `errors/native-error-ui.spec.mjs` and `errors/tool-limit-history-ui.spec.mjs`: use `process.env.PYTHON_BIN || "python3"` for fixture subprocesses. Class 2, match the sync suite's existing interpreter override convention.
