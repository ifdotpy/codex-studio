# Shell browser spec known failures

- `shell/shell-ux-ui.spec.mjs` — opening Search messages does not focus the query input. Reproduction: in an isolated fixture-backed browser with no sync/resource route mocks, click Search chats; the `Search all conversations` textbox remains inactive while `document.activeElement` is the dialog's Close button. `SearchOverlay.tsx:68-75` declares `autoFocus` on that textbox. Impact: keyboard users must manually move focus before typing into search. Suggested fix: add Mantine's `data-autofocus` to the query input so the focus trap selects it (untested). Exact origin/main check: not checked.
- `shell/shell-ux-ui.spec.mjs` — 320px responsive flow leaves Toggle conversations at x=-107..-63. The ancestor walk shows `#root.scrollLeft=113`, `scrollWidth=433`, and `main.workspace` at x=-113,width=320. This is the same root cause as the existing composer finding in `tests/client/KNOWN-FAILURES.md`: `.composer-submit-actions` overflows to x=433,width=408, and the root's retained horizontal scroll shifts both the composer and header. Root layout is `style.css:14-18`; the composer action row is `chat-controls.css:48-57`, with mobile wrapping in `appearance.css:601-609`. Impact: both composer content and the sidebar toggle move outside the phone viewport. Suggested fix: constrain the mobile composer action row so it cannot create horizontal overflow in `#root`. Exact origin/main check: not checked.
- `sidebar/sidebar-drag-browser.spec.mjs` — while the first `/api/projects` reorder response is deliberately held, a second `Alt+ArrowUp` reorder leaves `bodies.length === 1`; after releasing the first response, the displayed/server order remains only at the first move. The narrow expected-failure checks only that the second request is sent and later order applied; a normal twin verifies fixture setup and the held first save. Product guard: `web/src/components/useSidebarOrder.ts:127` silently returns when `busy.current` is set. Severity: low. Suggested fix: queue the second move, or disable the reorder control with an explicit busy state while saving. Exact origin/main check: product hook is identical to origin/main, so this behavior is not a regression from this branch.
