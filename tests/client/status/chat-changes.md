# Chat browser fixture changes

- `composer/composer-stability-ui.spec.mjs` — class 3. Limited the broad geometry comparison to desktop widths and added a narrow, isolated expected failure for the 390px send-control containment assertion. The earlier 40px composer height change was the first sent message removing the empty-chat account context row; it was a one-time content transition, not a send-state layout shift, so the stability baseline now starts after that transition.
- `composer/skill-autocomplete-ui.spec.mjs` — class 1. Wait for a rendered transcript message before checking ArrowUp prompt recall. The app can render the selected chat header/composer before the async transcript projection arrives; pressing ArrowUp earlier runs against an empty history. Focused rerun passes with the transcript readiness condition.
- `chat/ux-chat-ui.spec.mjs` / `tests/fixtures/ux-chat.tsx` — class 1 fixture repair for product commit `f4f176f1` (`Add unified agent setup and account tiles`), which made `Conversation.accountsState` required. The isolated fixture now supplies the same accounts data and state operations shape as `useAccounts`, preventing `Accounts` from dereferencing an absent state during render. It also serves the schema handshake, sync identity/protocol, transcript baseline and live resource invalidations that the real component needs; the restore case now publishes a newer transcript snapshot instead of only mutating test-local data. Replaced fixed waits with transcript and pending-page conditions, and close the open SSE response during cleanup so the test finishes under its existing timeout.
- `chat/prompt-navigation-ui.spec.mjs` — class 1. Added API schema headers and a current sync identity, served the seeded transcript through the scoped pull contract with increasing sequence numbers, and emitted fixture stream invalidations when the transcript changes. The fixture pull helper always used sequence 1, so post-update pulls after cursor 1 returned no document. The final metadata update now waits for its seq 5 pull before the spec's explicit reload. Reload diagnostic without that wait passed: the fixture returned seq 5 with the current snapshot for `after=4`; after reload the projection store held seq 5 and the next pull was `after=5` with no document. ArrowUp then loaded the older saved prompt. The handler is monotonic, not one-shot; the wait orders the test's final fixture update before reload, and the same-data post-reload path did not reproduce a product defect. No assertions were removed or weakened.
- `files/file-change-ui.spec.mjs` — class 1. The file cards render from the sync transcript projection. The fixture had replaced `EventSource` with a no-op and returned 404 for sync endpoints, leaving the transcript empty. Restore the real event stream, use the shared entity-state fixture for identity/protocol/baseline state, and serve transcript-scope pulls from the test data; include the schema hash on direct transcript responses. Focused run and repeat-three all pass.
- `files/upload-recovery-browser.spec.mjs` — class 1 fixture repair: the identity endpoint now returns the current API schema headers, so the quota failure and subsequent recovery flows run. The active coverage performs the two attachment updates sequentially. The isolated concurrent reproduction is retained as a skipped `test.fixme` while the product race is investigated; see `chat-known-failures.md`.
- `markdown/markdown-image-http-ui.spec.mjs` — class 1. The fixture rejected sync identity and returned a legacy transcript response, so the production chat list never hydrated. Use the fixture backend's identity/protocol contract, entity state, and transcript-scope pull with schema headers; the original HTTP and image-consent assertions now pass focused and repeat-three runs.
- `typography/original-typography-browser.spec.mjs` — class 2 stale expectation. `#conversation-status` now uses the shared `--studio-text-meta: 12px` minimum introduced by product commit `b05e7c35` (documented in `web/src/components/ui/README.md`); the test expected the pre-refactor 11px value. Updated that baseline while preserving the legacy-size checks for other controls and custom preference/reload coverage.
- `chat/chat-status-ui.spec.mjs` — class 1 fixture repair. The transcript-scope sync fixture always returned sequence 1, so after the client cached the initial completed agent metadata, later fixture state changes were ignored as already synchronized. Added an optional transcript sequence to the shared pull fixture and advance it whenever this spec refreshes state. This lets the active wait and final ended state reach the same production sync/cache path; the status assertions remain intact.
- `workspace/product-ui.spec.mjs` — class 2 selector update based on product commit `f4f176f1` (`Add unified agent setup and account tiles`). After opening Chat settings, the page contains both the persistent header `Main agent settings` button and the same labeled button within the settings dialog. Scope the latter click to the dialog so the existing model-options coverage still exercises the intended settings flow.
- `workspace/product-ui.spec.mjs` — class 3 mobile overflow isolation. Kept the 320px long-draft and message-input viewport checks active in the main flow; moved only the 320px `#send` viewport-bounds assertion into a separate expected-failure test. Reproduction selects the Release lead, hides the sidebar, then sets 320px viewport width.
- `workspace/session-activity-integration-ui.spec.mjs` — class 1 fixture repair. Added the current API schema hash to mocked sync responses so the entity pull hydrates the session activity strip. The late-history case now publishes an authenticated task-resource notification through `/api/sync/notify` after changing its task feed fixture, causing the real resource watcher to reload and restore the selected task. Existing assertions remain active.
- `workspace/work-log-ui.spec.mjs` — class 1 fixture repair. Replaced the all-404 sync route and no-op event stream with schema-valid entity pulls, a monotonic transcript projection, and authenticated transcript-resource notifications. Each update waits for its matching transcript pull before proceeding, so reload cannot race ahead of the fixture update. Existing work-log, disclosure, reload, and mobile assertions remain active.
