## Findings for owner

- `AgentPanel` returns `null` while there is no progress state (`web/src/components/agents/AgentPanel.tsx:196`). Controlled progress-fit experiments with the valid schema-checked identity held constant show that when the resource stream connects but sends no baseline (with handshake), or sends no handshake or baseline, the panel stays blank with no error or placeholder. In both runs the request log contains only `/api/sync/identity` plus the SSE resource subscription; no `/api/panel` request occurs and `pageErrors` is empty. This is a product finding for the owner, in the same family as “stream failing at first load shows no error.” The original fixture also needed `react/jsx-dev-runtime` in Vite's optimized dependencies (without it, the observed browser error was a missing `Fragment` export); the normal fixture now supplies schema identity and handshake/baseline and renders the panel.
- Execution settings drawer close button has no accessible name (screen readers announce an unlabeled button). `web/src/components/agents/ExecutionSettings.tsx:1128`. Confirmed in the mobile `Subagent defaults` accessibility snapshot: the banner contains a button with an image but no announced name, aria-label, or title. No product change made.
- The workspace worker overview has two controls named “Back to main agent”: `#back-lead` and `#lead-row` (`web/src/App.tsx:1607`, `web/src/components/shell/ConversationTitle.tsx:37`). The test scopes to `#back-lead` to avoid strict-mode ambiguity. The misc-group review classified this as a suspected minor accessibility issue; it has not been independently audited.
