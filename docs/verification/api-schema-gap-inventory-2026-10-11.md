# API schema gap inventory — 2026-10-11

This inventory records route declarations and gaps established before schema edits. It is conservative: `handler comparison open` means the route and OpenAPI operation were introspected, but the handler was not read, so completeness is not claimed. The introspection walked `FastAPI.routes` recursively through deferred `_IncludedRouter.original_router.routes` and compared effective methods and paths with `openapi_document()`.

Route table: 163 method/path entries (156 under `/api/`), including 14 hidden entries. The plan counted 150 decorators; this table counts effective method/path entries and includes FastAPI documentation, static app routes, and hidden fallback routes.

## Agents and work group audit — 2026-10-11

Compared 26 agents and 33 work operations against their handlers. Each route row now records its handler function line, declared status codes, shared error-envelope/header authority, route-specific error branches, and ETag/optional Server-Timing behavior. The current producer unconditionally sets all eight required fields when constructing the record at `codex_work.py:1158-1178`. `runId` and `attemptId` were present in 832, so only those two remain optional. The initial writer in `scripts/codex_work.py:259-270` (commit `4c64cca0`, 2026-09-06) already emitted the seven core fields; commit `a4654d75` (2026-10-01) added `resultFile` at submission and archive time. No general migration or read-time result backfill was found. The audited copy contains no result predating the `resultFile` addition, or another process filled it; which explanation applies is unknown. Top-level WorkItem fields retain prior optional/default behavior.

Flexible models: `AnswerBody` permits provider-specific JSON answer fields forwarded to `runtime.answer`; `NativePlanPayload` preserves provider notification fields passed through by the native event producer; both are genuine extension points. `VersionedRuntimeRecord` serves ToolRequestRecord, AgentRecord, and ComplaintRecord results, plus the tagged workspace inbox union assembled from RequestRecord, ComplaintRecord, WorkItem, AgentRecord, monitor, and RuleRecord values. Work records initialize `results` and `decisions` in `codex_work.py:1056-1057`, and result/decision producers populate their required fields in `codex_work.py:1149-1178` and `1202-1238`. Legacy-shaped test fixtures had omitted canonical result keys; updated `tests/entity-field-producers-contract.py`, `tests/mobile-startup-fixture.py`, and `tests/sync-state-seed-contract.py` to use the producer record shape. No disagreement was found in the runtime result producer; the work router and runtime suites are the evidence for representative generated values.
