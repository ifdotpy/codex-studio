# API schema gap inventory — 2026-10-11

This inventory records route declarations and gaps established before schema edits. It is conservative: `handler comparison open` means the route and OpenAPI operation were introspected, but the handler was not read, so completeness is not claimed. The introspection walked `FastAPI.routes` recursively through deferred `_IncludedRouter.original_router.routes` and compared effective methods and paths with `openapi_document()`.

Route table: 163 method/path entries (156 under `/api/`), including 14 hidden entries. The plan counted 150 decorators; this table counts effective method/path entries and includes FastAPI documentation, static app routes, and hidden fallback routes.

## Sync increment audit — /api/sync/*

Audited all seven sync operations through response construction, including relay POST /api/sync/notify. Each row above now lists handler and producer evidence. Handlers return the declared success models; shared ErrorResponse envelopes and middleware statuses are declared. Shared response utilities centralize header schemas and error-envelope models. No web call-site errors appeared under focused type checks, so no web source correction was required.

Flexible sync model outcomes (13 declarations before this increment): two known closed shapes were tightened; eleven remaining declarations are explicit extensions. NativeSafetyBufferingDto now directly references codex_records.NativeSafetyBufferingRecord and adds a closed schema annotation; the producer and _AGENT_FIELD_ALLOWLISTS both establish the exact set (native_notifications/dispatch.py:180-190, codex_records.py:733-743, codex_sync_entities.py:83-88). NativeNoticeDto is a union of the existing stored NativeNoticeRecord TypedDict and a typed provider-version warning shape because workspace_entity_view combines account_notices with codex_provider_versions.status()["warnings"] (codex_runtime.py:3759, codex_native_errors.py:177-195, codex_provider_versions.py:75-99,288-305).

The remaining extensible declarations and their established producer boundaries are: NativeProviderError (native app-server JSON errors, stored as JsonObject); question and request parameter/schema models (native question/elicitation protocols, codex_runtime.py:7942-7951, codex_questions.py:43-53, codex_records.py:422-439); RequestPreviewDto (raw native tool item preview at codex_runtime.py:8308); rate-limit window/bucket/data models (provider snapshots and extra window/reset-credit fields at codex_runtime.py:7659-7705,9090-9108); and DraftPayload (browser-owned document JSON metadata parsed and stored by codex_sync.py:567-630). These producers pass provider/user-owned JSON extension fields through, so retaining extra=allow is intentional and documented on the models.

This increment changes no response payload, status, field name, or header. Existing exact-byte route assertions and response validation suites passed. Its old schema hash was `19bca65689fede19184839765c1c9ca2528b402a3012a96522f5d4ec1a688c63`; its regenerated hash is `5e4ac0dbce4882a7e9f56933016ae1d68fcd518d8da05e2026d3531c76c6bdd8`. Clients must rebuild against each new hash; old-hash writes keep the existing HTTP 426 behavior.
