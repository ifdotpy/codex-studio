# Tooling, repository root and vendor boundary census

85 family rows cover tooling/root and vendor type families. Every scoped path is mechanically inventoried; function-level traces, output-only producers and unresolved downstream contracts are distinguished. No family count cap was applied. Highest follow-up priorities: generator semantic/numeric fidelity, saved gate evidence decoding, native usage arithmetic and signed/history compatibility. Vendor changes are upstream-only.

Source census and migration opportunities only. No runtime bugs asserted without a witness; every proposed witness is unrun. Source provenance discrepancy in Desk manifest is measured from target commit blobs, not a runtime defect.

All tracked files under workspaces/tooling, .agents, .config, .github, .githooks, workspaces/runtime/apps/layr and workspaces/runtime/apps/layr-desk, plus every repository-root file. Main workspace libraries excluded from census; named producer/consumer files outside scope followed selectively.

Function-level producer -> decode -> consumer inspection is recorded by family below. This is not a claim that every line was manually read. Dedicated test/fixture files were mechanically scanned; only relevant witnesses were inspected. External services' implementations and historical releases were not available and are explicitly unresolved where material.

D = fixed shape suitable for direct owner-typed decoding/removing generic intermediate (Rust Deserialize; in TS, use owner contract and a targeted boundary codec only where required—an annotation alone is NOT runtime validation). R = retain justified generic/raw boundary. A = already typed, with essential semantic checks retained. U = unresolved; no removal recommendation until named compatibility/provenance/caller proof. Priority is follow-up priority, not runtime defect severity.
