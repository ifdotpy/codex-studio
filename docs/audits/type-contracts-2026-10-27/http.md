R = retain a justified opaque/raw boundary or raw sidecar.

Common compatibility and validation obligations

1. json_body.rs:75 documents duplicate object keys using the last value. A direct typed byte deserializer may reject duplicate known fields; keep current semantics or make a separately approved contract change. Query names/cardinality/ASCII integer syntax and located errors also belong to the boundary.
2. Preserve missing versus explicit null, aliases, default application, numeric representation and safe-integer rules. JSON Schema integer acceptance and Rust integer Deserialize are not interchangeable. Vault number owners intentionally use serde_json::Number. Do not generalize one route's accepted 1.0 representation to every route.
3. generated_json (routes/mod.rs:112) is only serde_json::from_value. It does not perform the full OpenAPI schema walk. Primitive deserialization does not replace min/max, pattern, union correlation, collection schema, payload depth or runtime validity checks.
4. Schema-validation then typed-decode is only partly redundant shape checking. No blanket removal of Registry validation is justified. Stored/provider/CLI input is a separate trust boundary from the earlier HTTP validation; current debug response checks also cover constraints not represented by generated primitive fields.
5. Exact signed HTTP bytes, canonical parsed JSON receipts, normalized semantic signatures, exact stored document strings, and arbitrary JSON leaves are different contracts. Details below.
6. Ownership, permission, epoch/generation, version, freshness, current state, replay conflict, path/size, redaction, uncertain delivery, and reset-credit charging remain dynamic checks after types improve.
7. Source names below are concise: routes/... means workspaces/runtime/packages/runtime-http/src/routes/...; src/... and build.rs are relative to workspaces/runtime/packages/runtime-http/; services/... or a named service module means workspaces/runtime/packages/runtime-services/src/...; runtime-schema means workspaces/runtime/packages/runtime-schema/src/.... OpenAPI component locations are in this package's openapi.json. A line identifies the relevant declaration/call; grouped flows may span intervening lines.
