# Runtime services boundary census

Read-only systematic census at the named commit. Every tracked file is inventoried, all included source/fixture bodies read for inventory, and every production module assigned to a subsystem. Detailed regex candidate metrics apply to production-containing files. 82 logical family dispositions: 40 remove fixed Value/projection plumbing, 17 already typed, 11 retain raw/opaque boundary, 14 unresolved. 70 rows use focused source-body producer→decode→decision traces; 12 structural/declaration-call traces explicitly state limits. This is NOT a claim that every module/line/branch was manually read. No arbitrary top-N filter was applied. Findings are refactoring candidates, not demonstrated runtime defects; every witness is proposed, not executed.

See the [complete result](services.json) for exact inventory, metrics, methodology and inspection depth.
