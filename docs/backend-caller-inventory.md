## M-02.5 desktop packaging status

Issue #37 M-02.5 says Electron start, backend discovery, `package.mjs`, signing inputs and tests must work after relocation; a packaged artifact must launch without checkout-relative paths while preserving bundle ID, signing identity and browser profile. The issue records development discovery/tests as merged, but packaged macOS artifact, signing and native tests as unchecked.

Repository evidence: `backend.cjs` has development and packaged resource lookup; `package.mjs` copies backend source, diagnostics, Claude bridge and renderer into app resources, targets `darwin`/`arm64`, and sets bundle ID `local.codex.agents`; `main.cjs:66-77` preserves the existing Electron `userData` profile path across the app-name change. `signing.mjs` requires a persistent 40-hex signing identity and verifies codesign; `package-test.mjs` launches the packaged artifact hidden with temporary state/profile and checks backend persistence after desktop quit. Thus the code and bounded smoke-test path exist; there is no repository evidence here that the package was built, signed or launched successfully. The source config shows no checkout-relative path is intentionally used at runtime, but artifact proof is missing.

**Linux verification was not run.** The artifact flow is not executable on this host under the stated constraints: `package.mjs` hardcodes macOS arm64, invokes `xcrun swiftc`, then `codesign`/Keychain signing; the smoke test defaults to `Codex Studio-darwin-arm64` and uses Playwright Electron. The worktree has no `node_modules` or renderer `dist`, and `xcrun` is unavailable. Installing JavaScript dependencies into the worktree would violate the requirement to install only under `/var/tmp`; no Apple toolchain or macOS signing/launch environment is available on Linux. A Linux run cannot establish the M-02.5 packaged-macOS acceptance criteria. No windows were activated and no package, install, service or backend was run.
